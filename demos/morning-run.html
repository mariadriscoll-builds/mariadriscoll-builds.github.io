The morning run

A set of scheduled AI agents that keep a customer-success team's records current every day: what each client did, what was promised, what is overdue. I designed the workflow, wrote the agents' instructions and tuned them against what actually went wrong.

Why it exists

A small team was serving a growing list of clients whose crews used our product in the field. The signals about each client were spread across automated shift reports, daily system summaries, call recordings, calendars, three mailboxes and team chat. Nobody had time to read all of it, so commitments slipped and quiet clients went unnoticed until renewal.

Each client has a working file: a snapshot, an open-items list and a dated activity log. The agents keep those files true, so a person can open one and walk into a call prepared.

The schedule

Order matters. Each agent runs after the one whose output it depends on, so it can check its work against what the earlier one wrote instead of duplicating it.

Times are illustrative. The real schedule runs in the team's local time zone.

Measured, not assumed

After two weeks I counted which source each of about 200 activity-log entries had come from, and reordered the agent's reading list by what actually produced findings. Automated shift reports came first, not the convenient roll-ups.

Entries can cite more than one source. The support inbox was cited rarely but carried the most important customer email of one fortnight, so it stays in the sweep: cheap to read, expensive to skip.

The rules that make it trustworthy

An agent that writes confident nonsense into a client file is worse than no agent. Most of the work was finding the specific ways it could be wrong and writing a rule for each.

  • Check the source is current before trusting a quiet result

    Before reporting "nothing new", the agent checks when its source last updated.

    The call-transcript folder is filed by hand and once went five days stale. "No new customer quotes this week" would have read as "no customer said anything good", when really nobody had filed the calls.

  • Silence is not completion

    An item closes only on primary evidence that the thing happened: a document that arrived, an email actually sent, a meeting that ran. The agent quotes the source and the time.

    A wrongly closed item is worse than a stale open one, because a closed item stops being looked at.

  • Close what the item actually promised, and say what is still open

    A shipping record proves the part reached the client. It doesn't prove anyone told them, or that it was installed. Those stay open.

  • Relays are leads, not facts

    Summaries written by other tools are convenient but second-hand. The calendar wins on dates and times. The email wins on what a report said.

    A roll-up had a client meeting at 10:30. The invite said 12:00. The rule caught it before it reached the client's file.

  • "Unknown" is a true answer

    A unit with no fault reported is not "working". It is unknown until something shows it working, and every status carries the date it was last confirmed. An ageing date is the warning sign, so the agent never refreshes one it didn't re-check.

  • "Not yet due" is not "dead"

    If a daily feed hasn't arrived because the agent ran early, it says so. It doesn't raise a false outage.

  • Banter is not a commitment

    Joking and thinking aloud on a call don't become tasks. One meeting or deliverable is one item, not a bullet for every slide.

  • Stay in your lane, and prove you did

    Three writers touch the same files, and each owns specific sections. Before tidying a list, the agent backs up the file and checks afterwards that exactly the same lines exist. If they don't, it restores the file and reports instead of guessing.

A sample of the instructions

The agents run on plain-language instructions. This is a lightly edited excerpt.

Close only on primary evidence that the thing itself happened: a document that arrived, an email actually sent, a form returned, a calendar entry that exists, a meeting that ran. Quote the source and timestamp.

Never close on: the item going quiet; a call summary alone; someone asserting on a call that a thing is fine; or any inference needing a chain of reasoning.

An item that became unblocked rather than completed stays open, and gets flagged in the output.

What changed

The team lead opens the day to an up-to-date file for every client and a short list of what needs her. Promises made on calls show up as open items with an owner. Quiet clients surface in days instead of at renewal, and nothing is marked done without proof.
